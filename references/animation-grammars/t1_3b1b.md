# t1_3b1b · 3Blue1Brown-style math / concept visualization

> The grammar in one sentence: **on a black background, show only "the one thing being explained right now"; use smooth morphs (Transform) to turn the previous concept directly into the next; color = the concept's name; almost no cuts in the whole film.**
>
> Demo film: `scripts/engine/demos/t1_3b1b/` (render with `render.py --film demos/t1_3b1b`) (8s, 3 shots) · overview `assets/animation-grammars/t1_3b1b_overview.jpg` · code `scripts/engine/demos/t1_3b1b/`

## Pre-flight checks

1. **For each shot, write down "what turns into what".** What the previous object and the next object are (grid → circle, one curve → another, pixels → neurons). If you can't write that sentence about the morphing objects, don't use t1; switch to y5 or y3.
2. **The first frame is the object.** The coordinate system, grid or curve appears first; titles and formulas come after. Don't Write a line of title at second 0.
3. **Count the text on screen.** No more than 2 points on screen at once; before a third appears, the earlier ones either turn into a picture or are cleared away. Writing points one by one as a list is just PowerPoint on black.
4. **Write the color table first.** One color per concept; symbols in formulas share the color of their objects in the picture; no more than 4 semantic colors in the whole film.
5. **Hold still during waits.** No constant slow pushes, breathing or floating; the camera moves only when it's time to look at the next object, and stops when done (see ③ "Camera").

## ① When to use it

- **Use**: explaining how a mechanism "turns step by step into something else" — neural network forward passes, attention, matrix transformations, gradient descent, probability distributions, algorithm flows. Best when the narration is **action sentences** like "we flatten this image into a column", "each pixel is multiplied by a weight": each sentence maps to one Transform.
- **Use**: when the audience needs to "see the math" — symbols in a formula map one to one to objects in the picture (W in the formula is blue, and so are the connections).
- **Don't use**: product launches, emotional/brand films (black with white lines is too cold and too slow); real data trends (that's t3's job); narration that's opinion, story or punchlines (there's no object to "morph", so forcing it leaves only decoration). Fast cuts under 8 seconds don't suit it either — 3b1b's native rhythm is 1–3 seconds of animation + 1 second of hold (see ⑤); squeezing 3 shots into 8 seconds is already the limit.

## ③ Motion

- **Easing**: default `smooth = 6t⁵−15t⁴+10t³` (the 3b1b version, zero velocity and acceleration at both ends; the CE version is a sigmoid, `MO.smoothCE`). **Almost every animation uses it**; linear is only for Write, constant rotation and the advance of ShowPassingFlash. `there_and_back` for Indicate, `rush_into/rush_from` for "rushing in/out".
- **Default durations**: Animation run_time=1s, wait=1s. From 2023–24 source statistics: the most common explicit run_time is 2s (481 times) > 3s (333) > 1s (187) > 4s (145).
- **LaggedStart**: default lag_ratio 0.05; 0.1 is most common in the source. Implementation: `MO.lagged(i, n, p, r)` (item i occupies `[i·r, i·r+1]`, total length `1+(n−1)r`). In this film, 100 pixels → neurons use 0.01 (finishing in 1.1s), and 160 connections use 0.006.
- **Write**: linear; 1s for <15 sub-objects, otherwise 2s; lag between sub-objects = `min(4/(n+1), 0.2)`; each character is "outlined first, then filled" (`DG.math`/`DG.write`: lineDash advances the stroke → over the last 60% the fill fades in and the stroke fades out).
- **Transform**: both shapes are resampled to the same number of points with **aligned start points** (both starting from the upper-left direction, clockwise), with point-by-point straight interpolation (path_arc=0) + color interpolation. `DG.rectPts/circlePts/morph`. In this film: grid → circle (pixels → neurons), weight grid → flying into one neuron (weighted sum).
- **Entrances/exits**: FadeIn/FadeOut with shift (24–40px in this film, "from below upward" or "fading away upward"); neurons of a new layer fade in from 24px to the right; things being replaced shrink to a point and merge into the "⋮".
- **Signal**: ShowPassingFlash (time_width 2) — duplicate the connection, color it yellow, line width ×1.5, visible segment `[max(0,u−2), min(1,u)]` with u from 0 to 3 (`DG.flash`), staggered by input row with lag 0.04.
- **Camera**: frame animation as in MovingCameraScene; camera moves are events: hold → push to the next thing to look at → hold. Pushes default to 3b1b's native smooth single push (about 1s, `CAM.track` push/to); only the moment a conclusion lands gets a fast push (18–32% closer in 0.28 seconds, an accent, once or twice per section); 3D orbiting at 0.5–3°/s (3b1b default 1°/s) only when explaining spatial relations. In this film shot 2's push toward the output layer (1→1.08) is an event push; shot 1's constant slow push around the grid 1→1.025 is the old "slow push on every shot" habit — new films should not copy it.
- **Still during waits**: in the originals, waits are usually **static** — the biggest difference between 3b1b and keynote films. Don't add constant slow pushes, breathing or floating to fake motion; the motion comes from the next Transform.

## ④ Transitions (4 common ones)

1. **Continuation by Transform (no cut)**: the last frame of one shot = the first frame of the next; morphing turns the old object into the new one. In this film shot 1→2: 100 pixel squares become a column of input neurons, and shot 2's first frame is pixel-identical to shot 1's last frame. This is 3b1b's number-one transition, by a wide margin.
2. **Zoom through**: the camera pushes exponentially into an object (`zoom = Z^e`, constant perceived speed); the object's circumference becomes an opening with the new image inside. `TRANSITIONS.zoomThrough`, parameters `live:true` (the old shot keeps pushing its own camera when lt > duration, redrawing vectors so nothing blurs), `r0` (object radius), `zoom ≥ 1100/r0` (otherwise the opening doesn't fill the screen and the last frame jumps), `focus` (the new image's subject stays centered in the opening first, settling only after e>0.55). In this film shot 2→3: first the hidden neuron with activation 0.95 gets a yellow outline ("let's look at this one"), then the camera pushes 48× into it over 0.75s.
3. **FadeOut(shift=UP) + FadeIn(shift=UP)**: when switching topics, everything fades away upward and new content fades in from below (`TRANSITIONS.fadeShift`).
4. **ReplacementTransform for titles/formulas**: symbols of the old formula move to the positions of same-named symbols in the new formula (TransformMatchingTex, 2s by default in the 3b1b version); unmatched symbols fade out and in.

## ⑤ Rhythm and text

- **Shot duration**: the originals are continuous scenes, with single animations of 1–3s followed by a 1s wait; one "shot" (one concept) is often 8–20s. This film's 3 shots in 8 seconds (2.6/2.8/2.6s) is a **compressed version**; used with real narration it should be 2–3× longer.
- **Syncing with narration**: Grant's process is **animations first, voiceover after** ("I start by laying out all of the animations… then once I record the voiceover, the actual editing is like a day"). So the sync rule is "one sentence = one animation": the animation starts when the sentence says the action verb, and after the sentence lands, wait about 1s for the audience to look.
- **Text**: titles/questions are Written before the action (ask first, then show); formulas appear together with the picture in the same colors; numbers (0.95) count up with the fill and never appear before the picture. In Chinese, no more than one title line + one note line per screen (for English, keep it to similarly short lines).
- **FAQ principle**: "Every movement on the screen should be deliberate, with an identifiable purpose" — any motion without an explanatory purpose gets cut.

## ⑧ The 3 easiest mistakes

1. **Treating "glow" as 3b1b's signature and adding bloom and a deep-blue gradient background.** The originals are pure black + highly saturated thin lines + ×1.5 saturation, with almost no halos. Add halos and it becomes a "techy PowerPoint".
2. **Using only linear or generic ease, with animations that are too fast and too many.** The default must be smooth (the quintic polynomial), 1–3s per animation then a 1s hold; every action should correspond to a verb in the narration.
3. **Changing the color coding midway / too many colors.** One color = one concept, with formula symbols and picture objects in the same color; beyond 3–4 semantic colors, the audience can't remember them.
